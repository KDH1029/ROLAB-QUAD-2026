## 2. 작업공간 계보와 의존

```
merge_tmp ──(기술)──► rgosu ──► junsu ─────────────► 11-05 예선
    │                                    규정 변경(콘 고정·대형)
    └──────────────────────────────► junk ──► juninsu ─► 11-06 본선
```

미션 플래너들은 merge_tmp의 빌드 결과(`install/`)를 `source`해서 쓴다. 그래서 **merge_tmp를 먼저 빌드**해야 한다.

| 작업공간 | merge_tmp에서 쓰는 것 | 자기 작업공간(`ws_*`) |
|---|---|---|
| rgosu | go2_bridge, Hesai 드라이버, Unitree 메시지 | `ws_fastlio_tunable`, `ws_legfuse_gated`, `ws_ego_planner_tunable`, `ws_wall_filter` |
| junsu | 위와 같음 + 콘 추적기 | 위 + `ws_ego_review`, `ws_mission_vision` |
| junk / juninsu | go2_bridge, Hesai 드라이버, Unitree 메시지 | `ws_fastlio_tunable` |

내부 PC(Jetson Orin NX, ROS 2 Foxy) 쪽은 모든 플래너가 `onboard_vision/`(신호등 YOLO, TensorRT)을 같이 쓴다.

## 3. 공통 준비

| 항목 | 값 |
|---|---|
| NUC | Ubuntu 24.04, ROS 2 Jazzy, CycloneDDS(`rmw_cyclonedds_cpp`) |
| 내부 PC | JetPack 5, ROS 2 Foxy, TensorRT 8.5 |
| Unitree 메시지 | `~/unitree_ros2/cyclonedds_ws/install` |
| 파이썬 | `~/venv/go2` (numpy, scipy, matplotlib). OpenCV는 시스템 판을 쓴다. pip OpenCV로 덮으면 GStreamer 카메라 수신이 깨진다 |
| 커널 | `net.core.rmem_max`, `wmem_max` 128 MB. 기본값이면 XT16 점구름이 30% 버려진다 |
| DDS | 멀티캐스트는 디스커버리(spdp)만. 데이터까지 멀티캐스트하면 점구름이 100 Mb/s 포트를 넘쳐 XT16이 7.6 Hz로 떨어진다 |
| 로봇 | 엎드린 채 켜고, 기립 후 30초 안에 출발 (서 있기만 해도 뒷다리 hip 과열) |
| 재생 시험 | 별도 DDS 도메인 + 루프백. 로봇이 연결돼 있으면 스크립트가 거부한다 |

스크립트 안의 절대 경로(`~/ws/...`, `~/junsu_vision`)는 원래 개발 PC 기준이다. 다른 PC에서 쓸 때는 각 README의 "재사용할 때 고칠 곳"을 따른다.

## 4. 빌드

### 4.1 merge_tmp (먼저)

```bash
cd code/merge_tmp
source /opt/ros/jazzy/setup.bash
source ~/unitree_ros2/cyclonedds_ws/install/setup.bash
colcon build --symlink-install
source install/setup.bash
```

필요한 패키지: Nav2(`nav2_amcl`, `nav2_map_server`, `nav2_lifecycle_manager`), PCL(`pcl_ros`), Eigen3, Boost, yaml-cpp. FAST-LIO, Livox 메시지, Hesai 드라이버, Unitree 메시지는 `src/external`, `src/interfaces`에 들어 있다.

### 4.2 자율주행 미션 플래너 (junsu, rgosu)

```bash
cd code/junsu
source /opt/ros/jazzy/setup.bash
source ../merge_tmp/install/setup.bash
source ~/unitree_ros2/cyclonedds_ws/install/setup.bash
for ws in ws_fastlio_tunable ws_legfuse_gated ws_ego_review ws_ego_planner_tunable ws_wall_filter ws_mission_vision; do
  (cd $ws && colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release)
done
```
rgosu는 같은 방법으로 자기 폴더에 있는 `ws_*`만 빌드한다.

### 4.3 기록 경로 반복 미션 플래너 (juninsu, junk)

```bash
cd code/juninsu
source /opt/ros/jazzy/setup.bash && source ../merge_tmp/install/setup.bash
(cd ws_fastlio_tunable && colcon build --symlink-install --cmake-args -DCMAKE_BUILD_TYPE=Release)
```
관리자 스크립트가 `ws_wall_filter`, `ws_ego_planner_tunable`, `ws_mission_vision`도 source하려고 하지만, 경로 전용 모드에서는 쓰지 않으므로 없어도 된다.

### 4.4 내부 PC 비전

```bash
onboard_vision/deploy_onboard_vision.sh fp16     # 올리기 → TensorRT FP16 엔진 빌드 → 채점 (로봇 엎드려)
onboard_vision/deploy_onboard_vision.sh start    # 카메라 + 신호등 노드
```
- 엔진은 장치마다 새로 만든다. 빌드는 로봇이 엎드려 있을 때만 한다(`/lowstate`가 300 Hz 아래로 두 번 떨어지면 스크립트가 멈춘다).
- 기본은 FP16이다. INT8은 초록 재현율이 71%로 떨어졌다.
- 모델 선택: `TL_MODEL=tl_cone_1104|tl5cone`.

## 5. 실행

모든 관리자는 터미널 상태판 하나에서 키로 부품을 켜고 끈다. 로봇을 움직이는 키(`m` 모터, `r` 러너)는 운영자가 직접 누른다. 비상 정지는 `x` 또는 스페이스다.

### 5.1 merge_tmp: 위치추정 + 경로 계획만

```bash
./scripts/go2_run.sh --map maps/arena.yaml --start "0 0 0"     # --cones 라바콘 추적, --no-motor 모터 없이
python3 scripts/go2_goto.py --x 2.0 --y 1.0 --yaw 0             # 목표 (map 좌표)
./scripts/go2_run.sh --mode patrol                              # 보험: RANSAC 벽 따라가기
```
- 소프트웨어 정지: `ros2 lifecycle set /go2_cmd_vel_to_sport deactivate`
- 녹화본 시험: `GO2_RUN_TEST_LO=<도메인>` (루프백 전용)

### 5.2 junsu: 자율주행 미션 플래너 (예선)

```bash
tools/go2_ctl.sh                       # 실제 로봇
GO2_CTL_REPLAY=80 tools/go2_ctl.sh     # 녹화 재생 시험 (격리 도메인)
```
순서: `Q`(남은 부품 정리) → `a`(전체 켜기) → 상태판 전부 초록 → 출발 자리 → 리모컨 기립 → `m`(모터) → `r`(러너).

`a`가 켜는 부품:

| # | 부품 | 위치 | 하는 일 |
|---|---|---|---|
| 1 | XT16 드라이버 | merge_tmp | `/lidar_points` 20 Hz |
| 2 | 브리지 | merge_tmp `go2_bridge` (`tools/go2_bridge_lc.sh`) | IMU 500 Hz, 점구름 왜곡 보정, 다리 odom TF |
| 3 | FAST-LIO | `ws_fastlio_tunable` | 다리 속도 결합, 모션 게이팅, `det_range 30`, `max_range 15` |
| 4 | 벽 필터 | `ws_wall_filter` | 수직 벽만 `/mission/wall_cloud` |
| 5 | 장애물 합치기 | `src/obstacle_fusion_node.py` | 벽 + L1 낮은 점 + 카메라 콘 → `/mission/obstacle_cloud` |
| 6 | EGO-Planner | `ws_ego_review` | A* + 반발 포텐셜 B-스플라인, 격자 0.05 |
| 7 | 카메라·YOLO | 내부 PC `~/junsu_vision` | 정지선 신호등, 카메라 콘 |
| 8 | 위치 감시 | `tools/amcl_watch_core.py` | FAST-LIO와 AMCL 비교, 크게 어긋나면 ICP 재정렬 |
| – | 모터 | merge_tmp `cmd_vel_to_sport` | `m`. 직진 쏠림 보정 포함 |
| – | 러너 | `src/real_course_runner.py` | `r` / `R`(이어가기) |

경로 파일은 `maps/route_*.json`(본선 기본 `route_map_1106_user.json`)이고, 편집은 `tools/route_editor.py`로 한다. 자세한 키와 문제 해결은 `code/junsu/MANUAL.md`.

### 5.3 rgosu: 원형

```bash
tools/go2_full_stack.sh                 # 라이다 → 브리지 → FAST-LIO → 벽 → 합치기 → EGO → 모터 → 카메라 → 신호등
python3 src/real_course_runner.py       # 러너 (경로 파일·작전 값은 RUNNER_* 환경변수)
tools/go2_stop_all.sh                   # 전부 끄기
```

### 5.4 juninsu / junk: 기록 경로 반복 (본선)

```bash
~/go2_record/go2_record_auto.sh final1                  # ① 리모컨으로 한 바퀴 녹화 (/lidar_points, /lowstate 필수)
tools/make_map.sh ~/bags/<녹화 폴더> final1              # ② 녹화 → 지도 (FAST-LIO 재생 → 3D 복셀 → 2D pgm)
~/venv/go2/bin/python3 tools/route_editor.py final1     # ③ 지도 위에 경로 → routes/final1/route.json
~/venv/go2/bin/python3 tools/show_route.py final1       #    확인 그림 (벽·콘 0.25 m 안 = 빨강)
tools/junk_ctl.sh                                       # ④ Q → a → 출발 자리 → 리모컨 기립 → m → r
```
- 경로 편집기 점 종류: `1` start, `2` line(지나감), `4` stopline, `7` parking, `8` exit. 각도를 찍은 점은 멈춰서 그 방향으로 돈 뒤 동작하고, 각도 없는 점은 지나간다.
- 본선 기본 경로·지도는 `routes/rec1118x/`다.
- 관리자 기본 경로는 `routes/` 안에서 가장 최근에 고친 `route.json`이다. 시험용 폴더를 `routes/`에 만들면 그게 기본이 되니 주의한다.

### 5.5 YOLO 학습 (`code/yolo`)

```bash
yolo detect train data=ds_aug/data.yaml model=yolov8n.pt imgsz=1280 epochs=100 patience=20 batch=16
yolo export model=best.pt format=onnx imgsz=1280 opset=12 simplify=True dynamic=False
```
신호등이 작아서 1280 해상도를 쓴다. 가장 중요한 숫자는 초록불 정밀도다(초록 오판 = 빨간불에 출발).

## 6. 로봇 없이 시험

| 작업공간 | 명령 | 확인하는 것 |
|---|---|---|
| junsu / rgosu | `cd src && python3 test_real_course_runner.py` | 러너 상태기 (전부 PASS) |
| junsu | `cd sim && TMAX=420 CONE=det GUARD=off ./run_sim_v2.sh <이름> 80 <경로.json>` | 폐루프 시뮬 (결과 `sim/runs_v2/<이름>/report.txt`) |
| rgosu | `sim/run_sim.sh 420 5 0.25` | 폐루프 시뮬 v1 (도메인 79) |
| juninsu | `cd src && python3 test_path_mode.py && python3 test_park_profile.py` | 경로 모드, 주차 순서 |
| juninsu | `python3 debug/fullsim/sim_full_route.py` | 코스 랜덤 시뮬 (11-06: 40/40 완주) |
| merge_tmp | `test_plan_on_map <장애물.bin> <궤적.csv> …` | EGO-Planner 오프라인 계획 시험 |

시뮬레이터 로봇은 항상 잘 돌고 미끄러지지 않는다. 제자리 회전 실패나 콘 밀기는 재현되지 않으니, 시뮬 통과를 실기 통과로 보지 않는다.
