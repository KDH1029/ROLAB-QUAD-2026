# 트러블슈팅

## Sensor / Network

### 라이다 프레임 유실
- 증상: XT16 점구름 대량 유실
- 원인: 커널 UDP 수신 버퍼 기본값 208 KB. 1.4 MB 프레임이 조각나 하나만 잃어도 전체 폐기
- 해결: `rmem_max`, `wmem_max` 128 MB + DDS 수신 버퍼 64 MB. `RcvbufErrors` 58/s → 0, `/lidar_points` 7.5 → 20.1 Hz

### 대회 중 XT16 7.6 Hz
- 원인: 점구름이 멀티캐스트로 나가 100 Mb/s 포트 포화
- 해결: 멀티캐스트를 디스커버리(SPDP)에만 허용하는 별도 DDS 설정

### 원인 불명 급정지
- 원인: 다른 스택이 띄운 드라이버와 함께 두 드라이버가 같은 UDP 2368 포트 사용, 반쪽 스캔이 섞임
- 해결: 기동 전 포트(`ss -ulnp`)·발행자 수 확인, 다른 사람 프로세스가 있으면 기동 거부

### 로봇 전원 OFF 시 모든 노드 생성 실패
- 원인: DDS 설정 파일에 유선 인터페이스 이름 하드코딩
- 해결: 재생 시 루프백 설정을 환경변수로 덮어쓰기 (파일 수정 없음)

## Localization

### LIO-SAM 발산
- 처음 의심: 중력 상수(실측 9.437), GTSAM 버전 → 둘 다 A/B로 반증
- 원인: 파이썬 브리지 GIL로 IMU 500 → 48 Hz. 근본적으로 LIO-SAM은 9축 IMU 전용(Go2는 6축)
- 해결: FAST-LIO로 전환

### TF는 나오는데 위치가 틀림
- 원인: AMCL 오정합 (일치율 63.6%, 정지 중 yaw가 계속 바뀜)
- 해결: 모터 켜기 전 스캔-지도 일치율 80% 이상 확인

### 스캔과 지도가 기울어 안 맞음
- 원인: 지도가 너무 성김(점유 627칸), deskew 꺼짐
- 해결: 5,690칸 지도로 교체(일치율 35.6% → 100%), deskew 켬

### 초기 위치가 벽 안쪽으로 잡힘
- 원인: 로봇이 일어나기 전 엎드린 스캔으로 초기 자세 추정
- 해결: 기립 확인 후 초기 자세 추정

### FAST-LIO 궤적이 경기장 밖으로
- 증상: 7 × 6 m 경기장에서 25 m 밖으로 이동, 속도 경보 없음
- 원인: `det_range 60`. 지역 지도가 잘리지 않고 먼 점이 누적됨
- 해결: `det_range` 15(대회 30). 파라미터를 하나씩 바꾼 재생으로 특정

### 젯슨에서 FAST-LIO 프레임 43.5% 손실
- 원인: aarch64에서 OpenMP 비활성 → 스캔당 지연 1.5배 + 다른 노드 부하
- 해결: 연산을 NUC로 이전

### 전시장에서 지도 벽이 30~40 cm 번짐
- 원인: 15 m 이상 먼 점(구조물·관중)
- 해결: `preprocess.max_range 15`. 출렁임 p99 13.5 → 2.0 cm

### AMCL 위치 상실
- 원인: 차동 이동모델이 옆걸음을 반영하지 못함
- 해결: Omni 이동모델. 0.5 m 초과 시간 306 s → 0 s

### 라이브 FAST-LIO 발산
- 원인: L1 점구름이 입력으로 연결됨 (2분에 7,094 m 발산)
- 해결: XT16만 입력. 재생은 CycloneDDS로만 (FastDDS에서 비결정적 발산)

## Map / Planning

### 장애물 회피 불가
- 원인: 사전 장애물 층이 코스의 93%를 막음 (기울어진 지도를 단일 높이로 자름, 매핑 중 지나간 사람 포함)
- 해결: 바닥 평면 기준으로 자르고 자주 관측된 점만 유지. 자유공간 9.9 → 46.1 m²

### 경사로·계단을 벽으로 인식
- 원인: 계획기가 로봇 대비 높이만 판단
- 해결: 수직성 스캔(AMCL), 발밑 평면과 이어진 면 제거(연구, 가짜 장애물 13.9% → 1.0%)

### 지도 품질 지표 오측정
- 원인: 재구성 오류(외부파라미터 z 159 mm 차이), 평면 아닌 면 혼입, 로그 줄 수로 루프 집계
- 해결: FAST-LIO 출력으로 측정, 진짜 평면만 사용. 벽 두께 37 mm → 21 mm로 정정

## Robot control

### 직진 중 좌우 흔들림, 회전 보정 안 됨
- 원인: 너무 작은 속도 명령에는 발을 떼지 않음
- 해결: 최소 유효 명령 (0.10 m/s, 0.25 rad/s)

### 준비 중 로봇이 주저앉음
- 원인: 서 있기만 해도 뒷다리 hip 과열 (15분 79°C)
- 해결: 준비는 앉은 상태에서, 기립 후 30초 안에 출발

### 예선 주차 후 넘어짐
- 원인: 일어나는 중(높이 0.283 m)에 BalanceStand·걸음새 명령 전송
- 해결: 바닥 높이 확인 후 시간 측정, 높이 안정 확인 후 BalanceStand

### 걸음새 명령이 적용되지 않음
- 원인: BalanceStand가 아니면 ClassicWalk가 1 ms 만에 거절됨(-1), 응답 미확인
- 해결: BalanceStand 후 전송, 응답 확인 및 재전송

### 본선 정지선 후 29초 정체
- 원인: 39° 틀어진 상태에서 제자리 회전만 명령, 로봇이 회전하지 않음. 시뮬레이터에서는 재현 안 됨
- 해결: 1.5초에 3° 미만이면 전진하며 회전

### 직진 시 왼쪽으로 쏠림
- 원인: 기구적 쏠림. 첫 보정값은 실제 속도 기준으로 맞춰 과보정
- 해결: 명령 속도 기준으로 재보정, ClassicWalk 기준 재측정 (0.0156 / +0.0397)

### 출구 앞 정지
- 증상: 출구를 밀고 나가다 전방 장애물 판정으로 정지 (11-06, 2회)
- 원인: 러너의 완주 판정(몸 전체 통과)이 보수적

## Tools

### 재생 데이터가 실제 로봇에 섞임
- 원인: 같은 호스트의 DDS 참여자끼리 인터페이스와 무관하게 통신
- 해결: 재생 전용 DDS 도메인, 로봇 연결 시 재생 거부, 센서 토픽만 재생

### 감시 노드가 정상 주행을 정지시킴
- 원인: 주행에 쓰지 않는 FAST-LIO 신호를 감시
- 해결: z·점프·표류는 경고만, NaN·폭주만 정지

### 매핑 결과 저장 안 됨
- 원인: FAST-LIO 포크가 종료 시 PCD를 쓰지 않음
- 해결: 종료 전 `map_save` 서비스 호출

### 빈 지도 생성
- 원인: lifecycle 브리지를 활성화하지 않음
- 해결: configure → activate 추가

### 위치 확인 노드 즉시 종료
- 원인: 실행 스크립트 주석이 `SIM=false`를 삼켜 `use_sim_time:=`(빈 값) 전달
- 해결: 주석 위치 수정

### `pcd_to_pointcloud`로 지도가 안 보임 (Jazzy)
- 위치 인자 미지원 → `-p file_name:=<path>`
- 프레임 파라미터는 `tf_frame`
- `publishing_period_ms` 기본값이면 1회만 발행 → `500`

### 신호등 인식률 0%
- 원인: 모델 클래스 ID(0/1/2)와 노드 기대값(9/0/1) 불일치
- 해결: ID 매핑 수정, 출력 형식 자동 판별, letterbox 전처리 일치

### TensorRT 엔진 로드 실패
- 원인: TensorRT 8.5가 numpy 1.24에서 제거된 `np.bool` 사용
- 해결: `np.bool = bool` 보강

### 여러 작업이 같은 파일을 덮어씀
- 해결: 작업공간 분리, git 관리, 검증본 태그 고정
