## 3. 구현 방법

### 3.1 브리지 (`src/core/go2_bridge`)
- 5개 런타임 노드를 **lifecycle** 로: configure(퍼블리셔) → activate(구독·타이머) → deactivate.
  `cmd_vel_to_sport` 는 deactivate·Ctrl+C 시 StopMove(1003) 전송. Humble 호환을 위해 퍼블리셔 활성화는 명시 호출.
- `cloud_bridge` **수직성 스캔** (`scan_mode: vertical`, 기본값): 방위 1° 칸마다 인접 링 3개 이상이 같은
  수평 거리(±3 cm, 높이 폭 ≥ 8 cm)에 맞으면 벽. 경사로·계단 디딤면은 링이 올라갈수록 멀어져 통과 못 함.
  바닥 추정·로봇 높이 추정이 필요 없다.
- 기존 경사 필터(`slope`)의 EMA 지연 버그 수정 (10°·15° 경사를 벽으로 보던 문제).

### 3.2 매핑 (`mapper_node`, `scripts/go2_map_run.sh --lio`)
- 위치: FAST-LIO (`camera_init → body`) + FAST-LIO 가 보정한 `/cloud_registered`.
  다리 odom 위치는 바퀴마다 어긋나 벽이 겹쳐 그려졌다 (24.6 cm → 13.2 cm).
- 버그 수정: 키프레임 판정 프레임 혼용(4.5분에 9,430개 → 586개), `/scan` 을 고정 높이로 섞던 것,
  roll/pitch 무시, 근거리(로봇 몸) 필터 없음.
- 자동 수평: 매핑 궤적(로봇이 밟은 곳)에 RANSAC 평면 → 지도 회전. 궤적 없으면 점구름 최저점.
- 2D 판정: 칸별 바닥(1.0 m 칸, 20 %ile) 위 0.40~0.80 m 점이 8개 이상이면 벽 (`system_params.yaml`).
- 지도와 함께 궤적 저장(`*_traj.csv`) → 오프라인 평가에 사용.

### 3.3 SLAM
- FAST-LIO·Livox 메시지·Hesai 드라이버는 `src/external` 로 포크(소스 무수정). 설정은
  `config/fastlio/fastlio_xt16_odometry.yaml` (원본 포크: det_range 60→15, 외부파라미터).
- 입력은 반드시 XT16 `/lidar_points`. L1(`/utlidar/cloud`) 을 넣으면 2분 안에 수 km 발산(bag 재현).
- DDS 는 CycloneDDS. FastDDS 로는 재생 결과가 비결정적으로 발산했다.

### 3.4 위치추정 (AMCL, `go2_localization`)
- 원래 구성은 528 s 중 306 s 동안 위치 상실. 원인 분리 결과:
  차동 이동모델(옆걸음 무시)이 결정적 → **Omni** 로 0 s. 수직성 스캔이 추가 개선(p90 18 → 15 cm).
- AMCL 은 다리 odom 입력으로 SLAM 과 독립 (사용자 결정: AMCL 필수, SLAM 과신 금지).
- 출발 정렬 `scripts/go2_amcl_init.py`: 공분산을 담은 `/initialpose` + 정지 중 강제 갱신 20회.
  (`set_initial_pose` 는 공분산 0 이라 틀린 출발 위치를 못 고치고, AMCL 은 정지 중 갱신을 안 한다.)

### 3.5 경로 생성 (EGO-Planner, `src/core/ego_planner`)
- 상수 약 25개를 `config/ego_planner_params.yaml` 로 분리 (실행 중 변경: obs 높이, 속도, 여유 거리 등).
- 팽창(필수 0.28 m)과 반발(0.45 m) 분리, 가이드 경로 균등 재추출(코너 깎기), 궤적 검증
  (팽창 안에서 출발 시 빠져나가는 구간 허용), 충돌 예상 + 재계획 실패 시 정지, 속도 추정.
- 장애물 입력 `obstacle_source: scan` (수직성 스캔) / `cloud` (원래 높이 필터).
- 목표·콘 장애물이 `map` 으로 오면 AMCL 위치와 FAST-LIO 위치의 관계로 `camera_init` 에 옮긴다
  (재계획마다 다시 맞춤).
- `test_plan_on_map`: 기록 지도 위에서 걸은 경로 구간을 계획해 성공률·벽 이격 측정.

### 3.6 한 줄 실행 (`go2_navigation/launch/go2_stack.launch.py`, `scripts/go2_run.sh`)
- `mode:=nav`: imu/cloud/odom 브리지, FAST-LIO(`/tf_lio` 로 TF 분리), map_server, AMCL, EGO, (콘 추적), 모터 브리지.
- `mode:=patrol`: 브리지 + wall runner + 자세 브리지.
- lifecycle 매니저 하나(bond_timeout 0)가 순서대로 활성화, **모터 브리지는 마지막**.

### 3.7 RANSAC 보험 (`src/fallback/go2_wall_patrol`)
- `go2_patrol_ws` 의 wall runner 를 lifecycle 로 전환, 입력 선택:
  `scan` (수직성 스캔, 기본) / `cloud` (원래 링 7·8 슬라이스 — 몸이 기울면 같이 기울어 경사에서 바닥/벽 넘김).
- 코너 자세: StandDown 1005 → StandUp 1004 → BalanceStand 1002 (원래 코드 그대로, 보행 복귀 정상).

### 3.8 라바콘 위치 (`mission_vision/cone_tracker_node`)
```
YOLO 박스 ─ 1) 대략: depth 를 컬러 영상에 역투영, 박스 안 가까운 30 % (없으면 박스 아래 픽셀의 바닥 광선)
          ─ 2) 정밀: 대략 위치 반경 0.30 m · 바닥 위 3~25 cm 의 라이다 점 중심 → 앞면→축 보정
          ─ 3) base_link → map (촬영 시각 TF)
          ─ 4) 추적: 0.3 m 묶기, 라이다 측정이 위치를 결정, 3회(그중 라이다 2회) 확정
          ─ 5) 저장: 확정 시마다 ~/go2_cones.yaml, load_saved 로 재사용
출력: /mission/cones (PoseArray, map), /mission/cone_obstacles (EGO 장애물), /mission/cone_markers
```
- 라이다 정밀 단계는 카메라 외부파라미터가 아니라 라이다 외부파라미터에만 의존 → 카메라 캘리브레이션이
  조금 틀려도 최종 좌표가 흔들리지 않는다 (합성: 카메라 3° 오차에도 1.7 cm 그대로).
- YOLO 노드는 `vision_msgs/Detection2DArray` 로 박스를 낸다 (`/mission/cone_detections`).

### 3.9 카메라 캘리브레이션 (`mission_vision/tools`)
- `calib_target.py`: 노트북 전체화면 체커보드(8×6칸), 4칸 막대로 실제 칸 크기 측정.
- `calib_capture.py`: 카메라 평면(solvePnP) + 라이다 평면(화면 점 RANSAC)을 여러 기울기로 모아
  회전(법선 정렬, ≥3개 서로 다른 기울기) + 이동(거리 최소제곱) → `camera_extrinsics.yaml` 저장.
  `v` 로 라이다 점을 영상에 겹쳐 확인. 라이다가 화면을 못 잡으면 `--board-pose` (실측 보드 위치) 모드.

### 3.10 미션 FSM / YOLO 수정 (첫 커밋)

- FSM: 이전 정지선의 초록불로 출발하던 문제, 빨간불 시간초과 출발, map 없을 때 odom 으로 무음 폴백,

## 4. 알려진 문제 / 미검증

- **실기·대회장 검증 없음.** 모든 수치는 누리관 bag 또는 합성 데이터.
- FAST-LIO z 드리프트 (9분 +0.83 m). 2D 주행에는 z 를 쓰지 않지만 z 로 판단하는 로직 금지.
- patrol 보험: 수직성 스캔은 1° 간격이라 2 m 넘는 앞벽은 RANSAC 최소 점(20)을 못 채울 수 있다.
- `camera_extrinsics.yaml` 은 실측 장착(높이 0.417 m, 아래 32.1°)의 미보정 기본값.
- YOLO 모델은 합성(그림) 데이터 학습본. 실제 신호등 val 색 정답 16/53.
- 노트북 화면이 광택이면 라이다 평면이 약할 수 있다 → `--board-pose` 대체.
- 배터리(6S, BMS 없음): 전압 알람·퓨즈 필요, 전력 캡(PL1 15 W / PL2 25 W) 권장.
