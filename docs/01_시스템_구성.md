## 2. 네트워크

```
             ┌──────────── Go2 EDU ─────────────┐
 NUC16 ──유선─┤ 내부 PC 192.168.123.18 (카메라·YOLO)│
 (robot-br)  │ 로봇 제어부 · XT16 192.168.123.20    │
             └──────────────────────────────────┘
   │
   └─ Wi-Fi AP(NUC 핫스팟) ── 노트북 SSH   ※ 경기 중 센서 데이터 외부 전송 금지 → 화면은 글자 상태판만
```
- NUC 의 2.5GbE 포트 2개를 브리지(`robot-br`)로 묶어 로봇 쪽 게이트웨이로 썼다.
- DDS 는 CycloneDDS. 커널 소켓 버퍼 `rmem_max/wmem_max` 128 MB, DDS 수신 버퍼 최소 64 MB.
  멀티캐스트는 디스커버리(SPDP)에만 쓴다 — 점구름을 멀티캐스트로 내보내면 100 Mb/s 포트가 포화돼 XT16 이 7.6 Hz 로 떨어졌다([03 트러블슈팅](03_트러블슈팅.md)).
- 대회장 인터넷이 느려, NUC 를 부팅 때 자동으로 Wi-Fi AP 로 띄워 직접 SSH 했다.
- 시각 동기: 젯슨 보드는 RTC 배터리가 없어 인터넷 없는 대회장에서 시계가 틀어진다(TF 시각 오류로 Nav2 가 조용히 멈춤). NUC 에 chrony 시각 서버를 두었다. 카메라 타임스탬프는 내부 PC 시계(1970 기준)라 수신 시각과의 차이로 보정한다.

## 3. 소프트웨어 구성

### 3.1 자율주행 미션 플래너 (Rgosu → junsu)
```
hesai_ros_driver ─▶ go2_bridge(lifecycle) ─▶ FAST-LIO ─▶ wall_filter(벽 기억)
  /lidar_points      imu_bridge (IMU 500 Hz)      │              │
                     cloud_bridge (왜곡보정)       │     obstacle_fusion(벽 + L1 낮은 점 + 카메라 콘, 2초 기억)
                                                   ▼              ▼
                       AMCL(Omni) · 출발 정렬 ─▶ EGO-Planner(B-spline) ─▶ 코스 러너 ─▶ cmd_vel
                                                                           │   경로 파일 순서대로 목표,
                                                                           │   정지선·신호등·주차·출구 처리,
                                                                           │   막힘 복구(물러나기)·위치 감시
                                                    go2_bridge cmd_vel_to_sport ◀┘ (최소 유효 명령, 쏠림 보정)
                                                    → Unitree Sport API (ClassicWalk)
```
- 운영은 글자 화면 하나(`code/junsu/tools/go2_ctl.sh`)로 한다: 부품 켜기·재기동, 모터 켜기, 러너 시작·이어가기, 정비 정지, 비상 정지, 작전 값 바꾸기.
- 로봇 없이 같은 스택을 격리된 DDS 도메인에서 bag 재생·시뮬레이션으로 돌릴 수 있다.

### 3.2 기록 경로 반복 미션 플래너 (junk → juninsu)
실시간 경로 계획을 하는 일반적인 자율주행 알고리즘이 아니다. 규정 변경 뒤 확실히 완주하려고 만든 방식이다.
```
① 리모컨으로 코스를 한 바퀴 돌며 녹화 → make_map.sh: FAST-LIO 재생 → 3D 지도(2 cm) → 2D 지도(세로 25 cm 넘는 면 = 벽)
② route_editor.py: 지도 위에 점 찍기(start · line · stopline · parking · exit, 점별 바라볼 각도)
③ junk_ctl.sh → 러너: 출발 정렬 → 점을 순서대로 따라감(0.25 m/s, ClassicWalk)
     · 핀 구간: EGO 를 세우고 점들을 잇는 회귀 곡선을 직접 추종, 몸 방향 = 경로 방향
     · 앞 15 cm 안 물체면 전진 보류(3초), 5초 막히면 그 점 건너뜀
     · 정지선: 정지 → YOLO 신호 판정 → 출발 / 주차: 엎드리기 → 6초 → 일어나기 → BalanceStand
     · 멈춘 곳(출발·정지선·주차 뒤)에서만 AMCL 로 찾고 3D ICP 로 확인해 좌표 보정
```

### 3.3 로봇 내부 PC 비전
- 카메라 + YOLO(5 Hz, nice 19, 코어 제한)를 내부 PC 에서 돌리고, 결과(작은 JSON 문자열)만 NUC 로 보낸다. 원본 영상이 유선을 타지 않는다.
- Foxy ↔ Jazzy 사이에서 `vision_msgs` 같은 맞춤 메시지가 깨질 수 있어 `std_msgs/String`(JSON)을 쓴다.
- 내부 PC 는 로봇 펌웨어도 도는 PC 라, NUC 에서 `/lowstate` 빈도와 내부 PC 온도·부하를 감시한다.

## 4. 기술 계보

```
기반 기술     merge_tmp (위치추정·출발 정렬·계획 최적화·콘·카메라 캘리브레이션)     yolo (신호등·콘)
                  │                                                              │
미션 플래너   Rgosu ─▶ junsu        실시간 자율주행           ◀── 신호등 판정 ────┤
              ━━ 11-05 규정 변경: 콘 고정·대형(높이 0.7~0.8 m)·YOLO로 인식 불가 ━━ │
              junk ─▶ juninsu       기록 경로 반복             ◀── 신호등 판정 ────┘
로봇 보정     직진 쏠림 보정 → 모든 미션 플래너의 모터 명령에 적용
```
- junsu 는 Rgosu 폴더를 복사해 만들었고(코스 러너·전체 실행 스크립트), 그 위에 merge_tmp 의 기술을 얹었다.
- junsu 에서 `v2`(11-06 개선판)·`bak`(11-05 16:54 실주행 상태 되돌림용) 갈래가 나왔다. `code/junsu` 는 v2 최종판이다.
- junk 의 검증본은 태그 `nail-1105` 로 고정했고, 개발은 juninsu 에서 이어갔다.
- 카메라 캘리브레이션 도구(`camera_floor_calib`, `depth_lidar_align`)는 merge_tmp 이력(11-03 커밋 d19fb3c·5ac7b28)에 있고, 11-05 비전 정리(87e5781) 때 최신 판에서 빠졌다.

## 5. 대회 규정 요약 (로보월드 2026 사족보행)
- 일정: 11-04 자율 연습 · 11-05 예선 · 11-06 본선(자율) · 11-07 조종 본선
