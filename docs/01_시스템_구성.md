# 시스템 구성

## Hardware

| 구성 | 사양 | 용도 |
|---|---|---|
| 로봇 | Unitree Go2 EDU | IMU 500 Hz, 다리 odom 150 Hz, `/lowstate` 500 Hz |
| 주 라이다 | Hesai XT16 (16빔, 20 Hz) | FAST-LIO, AMCL, 장애물 |
| 보조 라이다 | Go2 내장 L1 | 발 앞 바닥, 낮은 장애물 |
| 카메라 | Intel D435i | 신호등, 콘 |
| 주 연산 | NUC (Core Ultra 7, 16코어), Ubuntu 24.04, ROS 2 Jazzy | 위치추정, 계획, 미션 |
| 내부 PC | Jetson Orin NX, ROS 2 Foxy | 카메라, YOLO |

## Network

- NUC 유선 포트 2개를 브리지로 묶어 로봇에 연결 (내부 PC `192.168.123.18`, XT16 `192.168.123.20`)
- DDS: CycloneDDS
  - 커널 `rmem_max`, `wmem_max` = 128 MB (기본 208 KB면 라이다 프레임 유실)
  - 멀티캐스트는 디스커버리에만 사용 (점구름 멀티캐스트 시 100 Mb/s 포트 포화)
- 시각 동기: NUC에 chrony 서버. 카메라 타임스탬프는 수신 시각 차이로 보정
- 경기 중 시각화(Foxglove) 끔 (센서 데이터 외부 전송 금지 규정)

## Software

### 자율주행 스택 (`rgosu`, `junsu`)

```
hesai_ros_driver → go2_bridge → FAST-LIO → wall_filter → obstacle_fusion → EGO-Planner → course runner → cmd_vel_to_sport
```

| 노드 | 역할 |
|---|---|
| go2_bridge | IMU 변환, 점구름 왜곡보정, 다리 odom TF (lifecycle) |
| FAST-LIO | 위치추정 (다리 속도 결합) |
| wall_filter | 라이다 링 정보로 수직 벽만 추출 |
| obstacle_fusion | 벽 + L1 낮은 점 + 카메라 콘 병합, 2초 유지 |
| EGO-Planner | 지역 경로 계획 |
| course runner | 목표 순서, 정지선·신호, 주차, 출구, 막힘 복구 |
| cmd_vel_to_sport | Sport API 변환, 최소 유효 명령, 직진 보정 |

실행·감시는 `code/junsu/tools/go2_ctl.sh`(터미널 관리자).

### 기록 경로 반복 (`junk`, `juninsu`)

1. 리모컨 주행 녹화
2. `make_map.sh`: FAST-LIO 재생 → 3D 지도(2 cm) → 2D 지도
3. `route_editor.py`: 경로점·정지선·주차·출구 입력
4. 러너: 출발 정렬 후 경로 추종, 정지 시점에만 위치 재확인

### 내부 PC 비전

- 카메라 + YOLO(TensorRT)를 내부 PC에서 실행, 결과만 NUC로 전송
- 5 Hz, nice 19, 코어 제한 (내부 PC는 로봇 펌웨어와 공유)
- 결과 형식: `std_msgs/String`(JSON). Foxy와 Jazzy 사이 `vision_msgs` 호환 문제 회피
