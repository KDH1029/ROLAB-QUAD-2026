# YOLO + D435i 깊이 → 콘 3D (11-04 아침, 10-30 녹화본 gosu_20261030_001126)

## 결론 (먼저)

1. **10-30 녹화본엔 라바콘이 하나도 없다.** conf 0.4 의 'cone' 191건은 **전부 오검출**이다(잘라낸 이미지를 눈으로 확인: 노랑·검정 경고 테이프, 나무 벽·경사로 모서리, 초록 테이프+ArUco 표식). pedestrian 70·temi 6·tl_green 1 도 전부 오검출이다(복도 전경, 나무 구조물). 그래서 이 녹화본으로는 **재현율(콘을 놓치는지)은 잴 수 없고**, 오검출률과 파이프라인 기하만 잴 수 있다.
2. **기하(박스 → 깊이 → 몸체 → 세계)는 맞다.** 검출 3D 점에서 FAST-LIO 지도까지 거리 중앙 **1.1 cm**, 96%가 5 cm 안이다(거리 0~6 m 어디서나 같음). 같은 정지 특징을 수 분 간격으로 다시 본 것의 세계 xy 퍼짐 중앙은 **3.2 cm**이고, 작은 특징이면 p90 이 3~6 cm 다. 넓은 물체는 p90 이 26 cm 까지 크다. 박스가 긴 테이프나 판자를 따라 미끄러진 것이라 파이프라인 오차로 보지 않는다.
3. **설정을 그대로(conf 0.4, 2회 확인) 실전에 쓰면 가짜 콘이 코스에 심긴다.** 542 s 동안 가짜 콘이 **21개** 확정되고, 시간의 **70%** 동안 적어도 하나가 떠 있다. **conf 0.6 + 3회 확인 + 모양검사**로 바꾸면 1개(6%)로 줄고, **conf 0.7 + 3회 + 모양검사**면 0개다. 다만 모양검사와 높은 문턱이 진짜 콘을 놓치게 하는지는 검증하지 못했다. **11-04 연습 때 콘을 놓고 녹화해야 정할 수 있다.**
4. **카메라에 콘 전체가 보이는 구간이 짧다.** 컬러 화면 위쪽 끝이 수평에서 9.5° 아래를 본다(아래로 32.1° 기울임, 높이 0.417 m). 그래서 콘 전체가 화면에 드는 건 **카메라 앞 0.32~1.12 m(몸체 원점 기준 약 0.8~1.6 m)** 뿐이다. 콘 밑면은 2.5 m 까지 보이지만 그보다 멀면 윗부분이 잘린다. 이 구간은 XT16 이 못 보는 발 앞 1.75 m 와 겹친다. 0.5 m/s 로 가면 콘이 온전히 보이는 시간은 약 1.6 s, 5 Hz 로 8프레임이다.
5. **노드 초안(cone_fusion_node.py)은 오프라인 재생 시험을 통과했다(DDS 없이).** 온라인 시계 오프셋(수신−stamp, 10 s 최솟값)과 고정 보정의 차이는 p1~p99 −8.3~+6.6 ms 다. 오프라인 결과와의 세계 좌표 차이는 중앙 0.07 cm, 최대 0.77 cm 다. CDR 바이트 직접 해석은 rclpy 역직렬화 결과와 60/60 일치했고, 컬러 기준 19배 빠르다.
6. **추론(CPU, 640, YOLOv8n)은 1프레임 20~60 ms다.** 다른 에이전트 3개가 같이 돌아서 부하에 따라 흔들렸다. 추출 중(4스레드) 실측은 p50 25 ms, p90 33 ms 다. 5 Hz 면 코어 하나의 10~30% 에 해당한다.

## ④ 노드 초안 `cone_fusion_node.py`

- 구독: 컬러·깊이·/Odometry_mux 를 모두 `raw=True` 로 받고, `cdr_parse.py` 로 numpy 해석한다. 처리 주기는 5 Hz 타이머다.
- 발행:
  - `/cone_fusion/points` (PointCloud2, camera_init): 확정 콘마다 반경 0.07 m 원판 격자 × 높이 0~0.25 m(0.05 간격)로 78점을 낸다. 지면 z0 기준이다.
  - `/cone_fusion/detections` (String JSON): 이번 프레임 검출 전부와 확정 콘 목록, status 를 낸다.
- 시계: 깊이 메시지마다 (수신−stamp)를 넣고, 최근 10 s 최솟값을 오프셋으로 쓴 뒤 δ −0.04 s 를 더한다. 이 δ 는 calib_depth_all.json 의 시각지연_s 다.
- 처리부는 ROS 와 떼어 `FusionCore` 로 만들었다. 노드와 오프라인 시험이 같은 코드를 쓴다.

## 남은 위험 / 할 일

1. **실제 콘 재현율을 잰 적이 없다.** 11-04 연습 때 콘을 0.5~3 m 에 놓고 녹화(record_all.sh)한 다음 `yd_extract.py` → `yd_3d.py` → `yd_gate.py` 를 그대로 돌려 conf·모양검사를 정해야 한다.
2. **파이썬 핫패스 규칙에 걸린다.** 컬러 1280×720 rgb8(2.7 MB, 17~30 Hz)와 깊이 30 Hz 를 rclpy 로 받는다. raw=True 라 역직렬화는 없지만, DDS 수신과 복사 비용은 재지 못했다(DDS 금지). 실측해서 크면 컬러 프로파일을 640×360 으로 낮추거나, 기존 C++ 브리지에서 5 Hz 로 솎아 다시 발행해야 한다.
3. **/Odometry_mux 헤더 stamp 가 NUC 시계인지 확인해야 한다.** 아니면 detections 의 status 가 계속 `no_pose` 로 나온다. 그때는 `-p odom_time:=recv` 로 바꾼다.
4. **콘 기억은 세계 좌표라 FAST-LIO 가 드리프트하면 같이 밀린다.** 30 s 유지를 줄이면 덜 밀린다(`keep_s`).
5. **ultralytics 를 쓰는 노드라 실행 파이썬은 ~/venv/go2 다.** 패키지는 하나도 설치하지 않았다.

| `yd_extract.py` | bag → 컬러 5 Hz YOLO + 최근접 깊이 저장 → `dets.npz`, `depth_frames.npy`(185 MB), `crops/`(눈 확인용 43장) |
| `cdr_parse.py` | raw CDR → numpy (Image, Odometry, 헤더) |
| `yd_core.py` | 순수 함수: 깊이→점, 투영, 박스 3D, 바닥, 모양검사, 점기둥, ClockOffset, PoseBuffer, ConeMemory, detect_to_world |
| `yd_3d.py` | 검출별 3D(몸체·세계) + 검증 → `det3d.json`, `summary.json` (`YD_FLIP_TX=1` → `_flip`) |
| `yd_table.py` | summary → 표 |
| `yd_gate.py` | 가짜 콘 문턱·확인·모양검사 스윕 → `gate_sweep.json` |
| `cone_fusion_node.py` | 실행 노드 초안 (rclpy, Jazzy) — **실행 안 함** |
| `test_cdr.py`, `test_node_offline.py`, `test_node_yolo.py`, `bench_infer.py` | 단위·재생·추론 시험 → `node_offline.json` |
